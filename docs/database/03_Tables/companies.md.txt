# 1. Purpose

The **companies** table is the root entity of the SaaS platform.

Every customer organization (tenant) that registers on the platform owns one record in this table.

Every tenant-specific resource references **company_id**.

Examples

- Users
- Documents
- Chat Sessions
- Tickets
- AI Settings
- Audit Logs

This table is one of the most important tables in the entire system.

---

# 2. Business Responsibilities

The companies table is responsible for:

# 3. Business Rules

### Rule 1

Each company represents exactly one tenant.

---

### Rule 2

A company can own many users.

---

### Rule 3

A company can own many documents.

---

### Rule 4

A company can own many support tickets.

---

### Rule 5

A company can own many chat sessions.

---

### Rule 6

Each company has one AI configuration.

---

### Rule 7

Deleting a company is prohibited.

Instead

```
status = INACTIVE
```

---

### Rule 8

Only Super Admin can permanently remove a company.

---

### Rule 9

Company name must be unique.

---

### Rule 10

Company slug must be unique.

# 14. SQLAlchemy Model Example

```python
class Company(Base):
    __tablename__ = "companies"

    company_id = mapped_column(BigInteger, primary_key=True)
    company_name = mapped_column(String(150), unique=True)
    company_slug = mapped_column(String(150), unique=True)
    email = mapped_column(String(255), unique=True)

    users = relationship("User", back_populates="company")
    documents = relationship("Document", back_populates="company")
    tickets = relationship("Ticket", back_populates="company")
```

# 19. Security Considerations

- Company Admins can only access their own company.
- Every repository query must filter by `company_id`.
- Never expose internal subscription data to customers.
- Audit all subscription changes.
- Encrypt sensitive configuration values.

---

# 20. Performance Considerations

- Cache company profile in Redis.
- Cache AI settings separately.
- Avoid joining company data on every request; resolve tenant context once per request and reuse it.
- Index subscription and status fields for dashboard queries.

# 22. Cursor AI Instructions

When generating code related to `companies`:

1. Never bypass CompanyService.
2. Always validate slug uniqueness.
3. Always enforce subscription limits.
4. Never hard-delete companies.
5. Filter tenant-specific queries using `company_id`.
6. Keep SQLAlchemy model, migration, repository, and documentation synchronized.
