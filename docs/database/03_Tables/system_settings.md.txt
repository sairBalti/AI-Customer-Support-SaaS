# 1. Purpose

The **system_settings** table stores global platform configuration shared across the entire application.

Unlike **ai_settings**, which stores company-specific AI configuration, this table contains platform-wide settings used by every tenant.

The settings stored here allow administrators to modify application behavior without changing source code or redeploying the platform.

Examples include:

- Platform maintenance mode
- Registration settings
- Default AI provider
- Default subscription plan
- Email configuration
- Password policies
- Security policies
- Storage providers
- Upload limits
- Global feature toggles

# 3. Business Rules

### Rule 1

There is only one active configuration for the platform.

---

### Rule 2

Only Super Administrators may modify system settings.

---

### Rule 3

Every configuration change must generate an Audit Log.

---

### Rule 4

Configuration changes must be versioned.

---

### Rule 5

Changes affecting security require administrator confirmation.

---

### Rule 6

Sensitive values are encrypted.

---

### Rule 7

The application should cache settings.

---

### Rule 8

Some settings require application restart while others support hot reload.

# 21. Security Considerations

- Only Super Administrators can modify settings.
- Encrypt sensitive configuration values.
- Audit every configuration change.
- Validate uploaded configuration values.
- Protect configuration APIs using RBAC.
- Cache encrypted settings securely.

---

# 22. Performance Considerations

- Cache all settings in memory.
- Reload only after updates.
- Avoid repeated database reads.
- Support hot reload for non-critical settings.
- Use distributed cache for clustered deployments.

# 27. Architecture Notes

Recommended architecture

```
Application Startup

↓

System Settings Loader

↓

Configuration Cache (Redis / Memory)

↓

Application Services

↓

AI Services

↓

Authentication

↓

Storage

↓

Email

↓

Notifications
```

The **system_settings** table is the central configuration authority for the entire platform. It provides a single source of truth for platform-wide behavior, security policies, default integrations, and operational settings. All services should consume configuration through a centralized configuration service with caching and validation rather than querying the database directly.
