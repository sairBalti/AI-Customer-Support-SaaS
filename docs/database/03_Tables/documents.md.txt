# 1. Purpose

The **documents** table stores every knowledge source uploaded by a company that can be used by the AI assistant to answer customer questions.

The actual file is stored in object storage (AWS S3, Azure Blob, Google Cloud Storage, MinIO, etc.).

The database stores only document metadata.

Once uploaded, documents pass through an AI processing pipeline:

```
Upload

↓

Virus Scan

↓

Text Extraction

↓

Chunking

↓

Embedding Generation

↓

Vector Database

↓

Ready for AI Search
```

The AI never reads the original document directly.

It retrieves relevant chunks from the vector database.

# 4. Business Rules

### Rule 1

Every document belongs to exactly one company.

---

### Rule 2

Every document has exactly one uploader.

---

### Rule 3

The uploaded file is immutable.

A new version creates a new processing cycle.

---

### Rule 4

Documents cannot be used until processing is completed successfully.

---

### Rule 5

Deleting a document removes:

- Knowledge chunks
- Embeddings
- Search indexes

Chat history remains unchanged.

---

### Rule 6

Files larger than the configured limit are rejected.

---

### Rule 7

Duplicate files are detected using SHA-256 hashes.

---

### Rule 8

Documents are soft deleted.

# 13. Processing Pipeline

```
Upload

↓

Virus Scan

↓

Extract Text

↓

Normalize Text

↓

↓

Generate Embeddings

↓

Store in Vector DB

↓

Mark Completed
```

If any step fails:

```
FAILED
```

The document is excluded from AI retrieval until successfully reprocessed.

# 15. SQLAlchemy Model Example

```python
class Document(Base):
    __tablename__ = "documents"

    document_id = mapped_column(
        BigInteger,
        primary_key=True
    )

    company_id = mapped_column(
        ForeignKey("companies.company_id"),
        nullable=False
    )

    uploaded_by = mapped_column(
        ForeignKey("users.user_id"),
        nullable=False
    )

    document_name = mapped_column(
        String(255),
        nullable=False
    )

    processing_status = mapped_column(
        String(50),
        default="UPLOADED"
    )

    company = relationship(
        "Company",
        back_populates="documents"
    )

    chunks = relationship(
        "KnowledgeChunk",
        back_populates="document",
        cascade="all, delete-orphan"
    )
```

# 20. Security Considerations

- Scan all uploaded files for malware.
- Restrict downloads to authorized users.
- Validate MIME type and extension.
- Never trust client-provided metadata.
- Encrypt files at rest.
- Use signed URLs for downloads.
- Log upload, delete, and reindex events.

---

# 21. Performance Considerations

- Store files outside MySQL.
- Use asynchronous background processing.
- Queue embedding generation.
- Cache document metadata.
- Batch indexing jobs.
- Track processing metrics for monitoring.

# 23. Cursor AI Instructions

When generating code for `documents`:

1. Never store file binaries in MySQL.
2. Always calculate SHA-256 hashes.
3. Use asynchronous processing for AI indexing.
4. Keep metadata and vector database synchronized.
5. Remove vector embeddings when documents are deleted.
6. Validate file size and MIME type before upload.
7. Enforce tenant isolation using `company_id`.
8. Keep migrations, ORM models, repositories, services, and documentation synchronized.
