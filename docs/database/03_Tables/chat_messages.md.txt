# 1. Purpose

The **chat_messages** table stores every message exchanged during a chat session.

A message may originate from:

- Customer
- AI Assistant
- Human Support Agent
- System

Every message belongs to exactly one chat session.

This table represents the complete conversation history and is one of the largest tables in the system.

It is optimized for:

- Conversation replay
- AI context generation
- Analytics
- Customer history
- Human escalation
- Compliance
- Auditing

---

# 2. Business Responsibilities

The chat_messages table is responsible for:

- Storing customer messages
- Storing AI responses
- Storing agent replies
- Maintaining conversation order
- Tracking token usage
- Tracking AI response time
- Tracking message feedback
- Storing AI citations
- Supporting conversation replay

---

# 3. Business Rules

### Rule 1

Every message belongs to one session.

---

### Rule 2

Messages are immutable.

Edits create a new revision (future enhancement).

---

### Rule 3

Messages are ordered chronologically.

---

### Rule 4

AI responses always reference the triggering customer message.

---

### Rule 5

Messages cannot exist without an active session.

---

### Rule 6

Deleting a session removes all messages.

---

### Rule 7

Messages are never shared across companies.

---

### Rule 8

Every AI answer stores retrieval metadata for traceability.

# 15. SQLAlchemy Model Example

```python
class ChatMessage(Base):

    __tablename__ = "chat_messages"

    message_id = mapped_column(
        BigInteger,
        primary_key=True
    )

    session_id = mapped_column(
        ForeignKey("chat_sessions.session_id"),
        nullable=False
    )

    company_id = mapped_column(
        ForeignKey("companies.company_id"),
        nullable=False
    )

    sender_id = mapped_column(
        ForeignKey("users.user_id")
    )

    parent_message_id = mapped_column(
        ForeignKey("chat_messages.message_id")
    )

    session = relationship(
        "ChatSession",
        back_populates="messages"
    )
```

# 21. Security Considerations

- Enforce tenant isolation.
- Escape HTML where necessary.
- Sanitize uploaded markdown.
- Encrypt sensitive metadata if required.
- Do not expose internal prompts to customers.
- Record moderation events.
- Support PII redaction.

# 24. Cursor AI Instructions

When generating code for `chat_messages`:

1. Never modify stored message text.
2. Save every AI response as a separate message.
3. Maintain strict chronological ordering.
4. Record token usage for AI messages.
5. Store citations and retrieved chunk references.
6. Keep session statistics synchronized.
7. Never expose hidden prompts.
8. Keep ORM models, migrations, repositories, services, and documentation synchronized.
