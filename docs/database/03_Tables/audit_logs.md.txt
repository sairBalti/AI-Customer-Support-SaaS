# 1. Purpose

The **audit_logs** table is the central source of truth for all critical system activities.

Every important business action performed by:

- Customers
- Support Agents
- Company Administrators
- Super Administrators
- AI Agents
- Background Workers
- System Services
- APIs

must be recorded in this table.

The audit log is immutable and exists to support:

- Security investigations
- Compliance requirements
- Legal evidence
- Debugging
- Incident response
- User accountability
- Change history
- Operational analytics

Unlike application logs, audit logs record **business events**, not technical events.

---

The audit_logs table is responsible for

---

# 3. Business Rules

### Rule 1

Every audit record belongs to one company.

---

### Rule 2

System-wide events may belong to the Platform Company (System Tenant).

---

### Rule 3

Audit records are immutable.

Updates are prohibited.

---

### Rule 4

Audit records are never deleted.

Retention policies archive old records.

---

### Rule 5

Every write operation affecting business data should create an audit record.

---

### Rule 6

Sensitive values must be masked before storage.

Passwords, API keys, tokens, secrets, and full payment information must never be stored.

---

### Rule 7

Every audit record must include who performed the action.

---

### Rule 8

Background jobs and AI agents must also create audit records.

# 21. Security Considerations

- Enforce tenant isolation.
- Restrict audit access to authorized administrators.
- Encrypt backups.
- Digitally sign exported audit reports if required.
- Never expose sensitive values.
- Log authorization failures.
- Record suspicious activities.
- Support immutable storage for regulatory environments.

---

# 22. Performance Considerations

- Partition large audit tables by date.
- Archive historical records.
- Compress archived partitions.
- Index common search fields.
- Avoid storing unnecessary payloads.
- Stream audit events to analytics platforms if needed.

# 24. Cursor AI Instructions

When generating code for `audit_logs`:

1. Never update or delete audit records.
2. Create audit records for every business-critical action.
3. Mask sensitive fields before storage.
4. Include request correlation IDs.
5. Record AI actions and background jobs.
6. Record authorization failures.
7. Ensure audit logging does not expose secrets.
8. Keep ORM models, migrations, repositories, services, and documentation synchronized.
