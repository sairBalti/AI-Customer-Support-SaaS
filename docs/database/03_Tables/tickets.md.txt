# 1. Purpose

The **tickets** table represents a customer support request that requires human intervention.

Tickets are created when:

- AI confidence score is below the configured threshold
- Customer explicitly requests a human agent
- AI cannot answer the question
- AI detects customer frustration
- Business workflow requires manual approval
- An administrator manually creates a ticket

Every ticket belongs to exactly one company and one customer.

A ticket may optionally originate from an AI chat session.

---

# 3. Business Rules

### Rule 1

Every ticket belongs to one company.

---

### Rule 2

Every ticket belongs to one customer.

---

### Rule 3

A ticket may have zero or one originating chat session.

---

### Rule 4

A ticket may have one assigned support agent.

---

### Rule 5

Closed tickets cannot receive new replies unless reopened.

---

### Rule 6

Tickets are never permanently deleted.

They are archived.

---

### Rule 7

Every ticket must have a priority.

---

### Rule 8

Every ticket must have a status.

---

### Rule 9

Every ticket receives a unique ticket number.

Example

```
SUP-2026-000001
```

---

### Rule 10

All ticket changes must be audited.

# 15. SQLAlchemy Model Example

```python
class Ticket(Base):

    __tablename__ = "tickets"

    ticket_id = mapped_column(
        BigInteger,
        primary_key=True
    )

    company_id = mapped_column(
        ForeignKey("companies.company_id"),
        nullable=False
    )

    customer_id = mapped_column(
        ForeignKey("users.user_id"),
        nullable=False
    )

    assigned_agent_id = mapped_column(
        ForeignKey("users.user_id")
    )

    session_id = mapped_column(
        ForeignKey("chat_sessions.session_id")
    )

    messages = relationship(
        "TicketMessage",
        back_populates="ticket",
        cascade="all, delete-orphan"
    )
```

# 21. Security Considerations

- Enforce tenant isolation using `company_id`.
- Customers can only access their own tickets.
- Agents only access assigned or authorized tickets.
- Administrators can access company tickets.
- Record every status change in audit logs.
- Prevent unauthorized assignment changes.

---

# 22. Performance Considerations

- Index frequently filtered columns.
- Cache dashboard metrics.
- Paginate ticket listings.
- Archive old closed tickets.
- Use background jobs for notifications.
- Precompute SLA metrics where practical.

When generating code for `tickets`:

4. Calculate SLA deadlines automatically.
5. Record all status changes.

7. Keep audit logs synchronized.
