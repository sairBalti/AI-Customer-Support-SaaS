# 1. Purpose

The **subscriptions** table stores every company's active and historical subscription.

This table determines which features, quotas, limits, AI capabilities, storage limits, and billing information are available for each tenant.

A company can have only one active subscription at a time, but historical subscriptions are preserved for reporting and auditing.

The subscription system supports:

- Free Trial
- Monthly Billing
- Annual Billing
- Enterprise Contracts
- Custom Plans
- Manual Billing
- Auto Renewal

# 3. Business Rules

### Rule 1

Every subscription belongs to one company.

---

### Rule 2

A company can have only one ACTIVE subscription.

---

### Rule 3

Historical subscriptions are never deleted.

---

### Rule 4

Subscription changes create Audit Logs.

---

### Rule 5

Expired subscriptions automatically become inactive.

---

### Rule 6

Feature access is determined from the active subscription.

---

### Rule 7

Trials automatically expire.

---

### Rule 8

Downgrades take effect at the next billing cycle unless immediate downgrade is requested.

---

### Rule 9

Enterprise subscriptions may not have automatic renewal.

# 15. SQLAlchemy Model Example

```python

    __tablename__ = "subscriptions"

    subscription_id = mapped_column(
        BigInteger,
        primary_key=True
    )

        ForeignKey("companies.company_id"),
        nullable=False
    )

    subscription_uuid = mapped_column(
        String(36),
        unique=True
    )

    created_by = mapped_column(
        ForeignKey("users.user_id")
    )
```

# 21. Security Considerations

- Only administrators may manage subscriptions.
- Validate payment provider webhooks.
- Audit all billing changes.
- Never trust client-side billing data.
- Encrypt external billing identifiers if required.
- Restrict billing APIs using RBAC.

---

# 22. Performance Considerations

- Cache active subscriptions.
- Cache feature entitlements.
- Schedule renewal jobs.
- Process billing asynchronously.
- Archive historical subscriptions.
- Avoid frequent entitlement queries.

It should integrate closely with authentication, authorization, AI settings, usage tracking, payment processing, and analytics while remaining flexible enough to support future pricing models and enterprise agreements.
