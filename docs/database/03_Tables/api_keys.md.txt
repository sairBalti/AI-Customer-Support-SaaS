# 1. Purpose

The **api_keys** table stores API credentials used to authenticate requests to the AI Customer Support Platform.

API Keys allow external applications to securely interact with the platform without requiring interactive user login.

Typical consumers include:

- Mobile Applications
- Company Websites
- Customer Portals
- CRM Systems
- ERP Systems
- Internal Microservices
- Third-party Integrations
- Automation Platforms

The platform never stores plaintext API keys.

Only securely hashed versions are stored.

---

# 2. Business Responsibilities

The api_keys table is responsible for

- API authentication
- Key lifecycle management
- Key rotation
- Expiration
- Permission scopes
- Rate limiting
- Usage statistics
- Security auditing

---

# 3. Business Rules

### Rule 1

Every API key belongs to exactly one company.

---

### Rule 2

Every API key is created by one user.

---

### Rule 3

Only the hashed value is stored.

Plaintext keys are displayed once during creation.

---

### Rule 4

Keys can be revoked but never modified.

Rotation creates a new key.

---

### Rule 5

Expired keys cannot authenticate.

---

### Rule 6

Inactive keys cannot authenticate.

---

### Rule 7

Every API request updates usage statistics asynchronously.

---

### Rule 8

Every API key must have permission scopes.

---

### Rule 9

API Keys are independent of user passwords.

# 22. Security Considerations

- Never store plaintext keys.
- Generate cryptographically secure random values.
- Display plaintext only once.
- Hash using SHA-256 or stronger.
- Use HTTPS exclusively.
- Support automatic key expiration.
- Rotate keys periodically.
- Record all key usage.
- Record failed authentication attempts.
- Support IP allowlists (future).
- Support HMAC signatures (future).

---

# 23. Performance Considerations

- Index key hashes.
- Cache validated keys.
- Update usage asynchronously.
- Use Redis for rate limiting.
- Batch analytics updates.
- Avoid unnecessary database writes.
