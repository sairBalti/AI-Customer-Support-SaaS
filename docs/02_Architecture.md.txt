# 3. Architecture Principles

## 3.1 Clean Architecture

Business logic must never depend on frameworks.

```
Presentation

↓

Application

↓

Domain

↓

Infrastructure
```

Dependencies always point inward.

---

## 3.2 SOLID

Every module must follow SOLID principles.

- Single Responsibility
- Open Closed
- Liskov Substitution
- Interface Segregation
- Dependency Inversion

---

## 3.3 DRY

Never duplicate business logic.

Extract reusable services.

---

## 3.4 KISS

Keep every solution simple.

Avoid unnecessary abstraction.

---

## 3.5 Separation of Concerns

Never mix

- API
- Business Logic
- Database
- AI Logic
- Authentication

Each belongs in its own layer.

# 7. Layer Responsibilities

## API Layer

Responsibilities

- Receive requests
- Validate request
- Call service
- Return response

Must NOT

- Query database
- Call AI directly
- Write business logic

---

## Service Layer

Responsibilities

Contains ALL business logic.

Responsible for

- Validation
- Rules
- Transactions
- Calling repositories
- Calling AI

---

## Repository Layer

Responsibilities

Only database queries.

Must never

- Validate business rules
- Generate AI responses
- Perform authentication

---

## Domain Models

Contain

- Entities
- Business Objects
- Enumerations

---

## Infrastructure

Contains

- MySQL
- Redis
- ChromaDB
- S3
- SMTP
- OpenAI SDK

# 30. Cursor AI Development Rules

Before generating code, Cursor should:

1. Read `01_PRD.md` to understand the feature.
2. Read `02_Architecture.md` to determine where the code belongs.
3. Follow Clean Architecture strictly.
4. Never place business logic in routers.
5. Always use dependency injection.
6. Reuse existing services before creating new ones.
7. Write type hints and docstrings.
8. Add tests for new functionality.
9. Update documentation when APIs or architecture change.
10. Keep modules cohesive and avoid circular dependencies.

---

# 31. Definition of Done

A feature is considered complete when:

- Functional requirements are implemented.
- Unit tests pass.
- Integration tests pass.
- Code follows architecture guidelines.
- Security checks are satisfied.
- Documentation is updated.
- Logging and error handling are included.
- Performance targets are met.
- Code review is completed.
